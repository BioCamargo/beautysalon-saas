7. Inconsistências Encontradas nos Testes Reais & Ajustes Realizados no Código 4 Ajustes Corrigidos no Código
# Módulo / Funcionalidade Problema Encontrado durante a Simulação Humana Correção Implementada
BUG-01 Cadastro de Clientes, Ausências & Agendamento Online (Datas HTML5) Os campos HTML <input type="date"> dos navegadores enviam datas no formato ISO (yyyy-MM-dd, ex: 1994-11-20), mas o StringToLocalDateConverter.java aceitava exclusivamente o formato dd/MM/yyyy. Isso causava erro de conversão (DateTimeParseException) ao preencher a data de aniversário no cadastro de clientes ou no agendamento público online. Atualizado StringToLocalDateConverter.java, GlobalDataBinderAdvice.java, ClienteDTO.java, UserController.java e AgendamentoPublicoController.java para aceitar tanto ISO (yyyy-MM-dd) quanto formato brasileiro (dd/MM/yyyy).
BUG-02 Tela de Sucesso do Agendamento Público (Link Google Agenda) No template templates/publico/sucesso.html (linhas 476-477), o script que monta o botão "Adicionar ao Meu Google Agenda" referenciava uma variável JavaScript inexistente ${salao} em vez de ${empresaNome}, gerando ReferenceError: salao is not defined e impedindo o botão do Google Agenda de funcionar. Corrigido em templates/publico/sucesso.html para utilizar a variável ${empresaNome} definida na linha 451.
BUG-03 Fechamento de Comanda com Split de Pagamentos Quando o operador registrava pagamentos parciais (Split: ex. PIX + Cartão), o <select name="formaPagamento"> era ocultado pelo Thymeleaf (th:if="${#lists.isEmpty(comanda.pagamentos)}"), mas o método fecharComanda no FinanceiroController.java exigia @RequestParam String formaPagamento obrigatório, podendo causar erro 400 ao clicar em "Receber & Fechar Comanda". Ajustado FinanceiroController.java para @RequestParam(required = false, defaultValue = "MULTIPLO") String formaPagamento.
BUG-04 Cálculo Server-Side de Cupom de Desconto na Comanda O método fecharComanda em FinanceiroService.java salvava o código do cupom (cupomCodigo), mas dependia apenas do JavaScript do navegador para preencher o campo desconto e não incrementava o contador usosAtuais do cupom no banco. Atualizado FinanceiroService.java para validar o cupom no servidor, aplicar automaticamente o desconto (percentual ou valor fixo) caso não tenha vindo preenchido e incrementar usosAtuais.
